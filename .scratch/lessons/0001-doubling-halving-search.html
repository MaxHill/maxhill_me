The Doubling / Halving Search

Finding the smallest entropy size that still crashes the SUT.

Why not literal binary search?

You don't know the upper bound up front. Binary search requires [lo, hi] with hi known to fail and lo known to pass. We start with neither.

The article's algorithm has two phases:

  1. Doubling phase (climb). Start small. While we keep passing, double the step and grow size. We're hunting for any failure. Each pass-pass means "we're climbing too slowly" → double the step.
  2. Halving phase (descend). Once we hit a failure, flip direction: subtract the step from size to try smaller. While shrinking still fails, keep the same step. The moment we cross back into passing, halve the step (we overshot) and stay at the last failing size. Repeat until step reaches 0.

The result is the smallest failing size we encountered.

State

Five variables. Yes, that's a lot — write them out.

size       : current "settled" size (the last one we accept as a baseline)
step       : how far the next attempt jumps from `size`
pass       : did the last attempt at `size` pass? (initially: assume yes)
found_size : smallest failing size seen so far (option)
found_seed : the seed that triggered that failure

The loop, in plain English

Each iteration:

  1. Compute size_next:
    • if pass: size + step (climbing — try bigger)
    • if not pass: max 0 (size - step) (descending — try smaller, clamped at 0)
  2. Stop conditions: step = 0, or size_next > size_max, or safety counter exhausted.
  3. Run run_multiple ~size:size_next ~attempts. Get outcome → pass_next.
  4. If pass_next is Found_fail, record (size_next, seed) as the new best found_*.
  5. Update step:
    • both pass && pass_next: still climbing comfortably → step *= 2
    • both (not pass) && (not pass_next): still shrinking and still failing → keep step
    • mixed (we just crossed the boundary): we overshot → step / 2
  6. Update size and pass:
    • if pass || not pass_next: adopt size_next. (We were climbing, OR the new attempt also failed — both cases extend our knowledge.)
    • else (not pass && pass_next): don't adopt. We were at a failing size and a smaller probe just passed — keep our failing baseline, just shrink the step.
Key insight. The asymmetry in step 6 is the heart of the algorithm: once we've seen a failure, we never voluntarily walk back to a passing size. We only narrow our step down toward it.

OCaml shape

OCaml doesn't have mutable locals by default, so the natural shape is recursion with state as parameters. 

type search_outcome =
  | Search_pass
  | Search_fail of { size : int; seed : int }

let search ~sut_path ~attempts ~size_max : search_outcome =
  let rec loop ~iter ~size ~step ~pass ~found =
    if iter >= 1024 then failwith "safety counter"
    else if step = 0 then found
    else
      let size_next =
        if pass then size + step
        else max 0 (size - step)
      in
      if size_next > size_max then found
      else
        let outcome = run_multiple ~sut_path ~size:size_next ~attempts in
        let pass_next, found =
          match outcome with
          | All_pass ->
              Logs.info (fun m -> m "pass size=%d" size_next);
              true, found
          | Found_fail seed ->
              Logs.err (fun m -> m "fail size=%d seed=%d" size_next seed);
              false, Some (size_next, seed)
        in
        let step_next =
          if pass = pass_next then
            (if pass then step * 2 else step)
          else
            step / 2
        in
        let size_new, pass_new =
          if pass || not pass_next then size_next, pass_next
          else size, pass
        in
        loop ~iter:(iter+1) ~size:size_new ~step:step_next
             ~pass:pass_new ~found
  in
  let result =
    loop ~iter:0 ~size:16 ~step:16 ~pass:true ~found:None
  in
  match result with
  | None -> Search_pass
  | Some (size, seed) -> Search_fail { size; seed }

Things worth noticing

  • Initial pass = true. We haven't actually run anything yet. Assuming "pass" means the first iteration goes into the climbing branch and tries size_next = 16 + 16 = 32. Size 16 itself is never directly tested — fine, the algorithm finds it later if it matters.
  • max 0 (size - step). OCaml ints don't saturate on underflow; they go negative. Clamp manually.
  • Condensed step update. if pass = pass_next then … covers both same-direction cases. The else branch is the boundary cross.
  • Logs. Logs.info for passes, Logs.err for fails. Set the log level to Info in main and watch the search run live — very satisfying.
