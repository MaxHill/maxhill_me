Lesson 02 · OCaml + FRNG · The Payoff

The Toy World

A tiny ledger, a planted bug, and an automated minimizer that finds the smallest failing scenario.

The point

So far your SUT is hard-coded to fail at entropy >= 50. The searcher works, but there's nothing interesting to minimize. A real World has:

  • Internal state that evolves over time.
  • Multiple actions chosen randomly via weighted_pick.
  • An invariant asserted after every step.
  • A bug that requires a specific sequence of choices to expose.

When you wire that into the searcher, the minimum size becomes "the entropy needed to make the bug trigger reliably enough that 100 attempts find it." That's the article's whole vibe.

Design: the two-account ledger

Small enough to fit in your head, big enough to make minimization meaningful.

type world = {
  mutable a : int;
  mutable b : int;
  frng      : FRNG.t;
}

init: a = 5, b = 5

actions (weighted):
  | Transfer_a_to_b   (* pick amount 1..3, a -= amt, b += amt *)
  | Transfer_b_to_a   (* pick amount 1..3, b -= amt, a += amt *)
  | Inquiry           (* no-op, just consumes a tiny bit of entropy *)

invariants (asserted every step):
  a + b = 10
  a >= 0
  b >= 0

planted bug:
  the transfer functions don't check that the source has enough balance.
  enough one-direction transfers will drive a (or b) negative.

Why this is good for the searcher

  • The total invariant a + b = 10 always holds (transfers conserve mass), so no false positives there.
  • The >= 0 invariant can break, but only after at least 2-3 transfers in one direction without offsetting transfers.
  • A single action isn't enough → the minimum size is meaningfully > 0.
  • With balanced weights, ~half of transfers go each way, so getting a streak takes many attempts at small sizes — exactly what run_multiple is designed for.

Each step's entropy budget

Roughly per step:

  • weighted_pick over 3 actions → 8 bytes (one take_int for the bound)
  • amount draw 1..3 → 8 bytes (another take_int)
  • ~16 bytes per step

So 3 transfers in a row ≈ 48 bytes. Plus swarm_weights setup costs a few more upfront. Expect the searcher to converge to a minimum around 80-150 bytes.

Code shape

A new module lib/World.ml:

module FRNG = FRNG

let ( let* ) = Result.bind

type t = {
  mutable a : int;
  mutable b : int;
  frng : FRNG.t;
}

type action_weights = {
  transfer_a_to_b : int;
  transfer_b_to_a : int;
  inquiry         : int;
}

(* Pick random weights at the start so different runs explore
   different action distributions. *)
let init_weights frng =
  let* transfer_a_to_b = FRNG.take_range_inclusive frng ~min:1 ~max:100 in
  let* transfer_b_to_a = FRNG.take_range_inclusive frng ~min:1 ~max:100 in
  let* inquiry         = FRNG.take_range_inclusive frng ~min:1 ~max:100 in
  Ok { transfer_a_to_b; transfer_b_to_a; inquiry }

let init frng =
  let* _weights = init_weights frng in
  (* For now we ignore weights — could thread them through if you want. *)
  Ok { a = 5; b = 5; frng }

let check_invariants w =
  assert (w.a + w.b = 10);
  assert (w.a >= 0);
  assert (w.b >= 0)

let step w =
  let* action =
    FRNG.weighted_pick w.frng [
      `Transfer_a_to_b, 10;
      `Transfer_b_to_a, 10;
      `Inquiry,          1;
    ]
  in
  let* () =
    match action with
    | `Transfer_a_to_b ->
        let* amt = FRNG.take_range_inclusive w.frng ~min:1 ~max:3 in
        w.a <- w.a - amt;
        w.b <- w.b + amt;
        Ok ()
    | `Transfer_b_to_a ->
        let* amt = FRNG.take_range_inclusive w.frng ~min:1 ~max:3 in
        w.b <- w.b - amt;
        w.a <- w.a + amt;
        Ok ()
    | `Inquiry ->
        Ok ()
  in
  check_invariants w;
  Ok ()

let run w =
  let rec loop () =
    match step w with
    | Ok () -> loop ()
    | Error FRNG.Out_of_entropy -> ()
  in
  loop ()

Notes

  • The bug is implicit, not explicit — Transfer_a_to_b doesn't check w.a >= amt. That's the bug. It blindly subtracts. The invariant a >= 0 will catch it via assert.
  • assert is what crashes the SUT. When the assertion fails, OCaml raises Assert_failure, the program exits nonzero, and the Driver counts it as Fail. The searcher minimizes from there.
  • The let* () = ... in pattern threads results through unit-returning operations. Common OCaml idiom for "do this side-effecting thing, but propagate any error."
  • Module aliases. module FRNG = FRNG at the top is stylistic — makes FRNG.foo references explicit even within Sync_simulator. Skip if you prefer.

Wiring into the SUT

bin/sut.ml becomes:

let () =
  let entropy = In_channel.input_all stdin in
  let frng = Sync_simulator.FRNG.init entropy in
  match Sync_simulator.World.init frng with
  | Error Sync_simulator.FRNG.Out_of_entropy ->
      (* not enough entropy to even start the world — innocent *)
      exit 0
  | Ok w ->
      Sync_simulator.World.run w;
      exit 0
Innocent until proven guilty. If entropy runs out during init or during a step, that's not a bug — it's just a too-short input. Exit 0. Only an assert failure (which exits nonzero via uncaught exception) signals "found a bug."

Your task

  1. Create lib/World.ml with the structure above.
  2. Rewrite bin/sut.ml to drive it.
  3. Build and sanity-check with a tiny replay: 
    mise run replay -- --seed 42 --size 64
    Should pass or fail depending on the seed/size.
  4. Run the search. 
    mise run search -- --attempts 100 --size_max 4096
    Watch it climb, find a fail, then minimize. Expect convergence to something in the 50-200 byte range. Some pass size=N log lines, then fail size=M seed=K as it homes in.
  5. Reproduce the minimum. The searcher prints minimized size=N seed=K. Plug those into replay: 
    mise run replay -- --seed K --size N
    Should fail deterministically — that's your minimal counter-example.
